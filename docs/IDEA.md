# 项目工程需求说明书：hiveproxy

你是一位精通分布式系统架构的 Rust/Tauri 资深开发专家。你的任务是设计并实现一个去中心化、零配置的 P2P 传输层网格网络代理工具，项目命名为 **hiveproxy**。

## 1. 项目背景与痛点
*   **网络环境**：大量主机终端分散在不同的网段/子网中。网络层（L3）的跨网段流量被企业防火墙严格阻断。
*   **单向白名单孔洞**：IT 防火墙策略允许特定的、单向的端口访问（例如：A 网段的机器可以通过 5678 端口访问 B 网段的机器，但 B 无法主动发起物理连接连回 A）。同网段内的机器默认完全互通。
*   **核心目标**：彻底干掉繁琐的、多级的 frp 配置文件。在所有机器上运行同一个软件程序。每台机器启动后自动生成一个全局唯一的 UUID。利用 IT 留下的单向白名单孔洞建立长连接，并通过去中心化 Gossip 协议交换拓扑结构。在传输层内存中实现多跳中继（Multi-Hop Relay），最终在本地释放一个统一的 SOCKS5 代理端口（`127.0.0.1:1080`），实现全网终端的透明、双向无感访问。

## 2. 技术栈与硬性约束
*   **后端核心**：Rust 语言（使用 `tokio` 异步运行时处理高并发 Socket 读写；使用 `serde` 进行高效序列化；使用 `petgraph` 图算法库基于 Dijkstra 算法计算最短中继路径）。
*   **前端与 IPC 绑定**：Tauri v2。前端 UI 负责可视化监控（展示蜂巢网络拓扑、实时连接控制）；Rust 后端负责核心网络引擎。
*   **协议层约束**：必须完全在**传输层/应用层（Layer 4 / Layer 7）**的用户态 TCP Socket 上进行操作。为了规避不同操作系统的 Root/Administrator 管理员权限壁垒，**绝对不要**使用 TUN/TAP 虚拟网卡技术。

## 3. 传输层覆盖网络协议设计（二进制帧格式）
全网的 Gossip 控制信号、心跳包以及业务代理流量共同复用同一条长连接 TCP 流。我们需要在裸 TCP 流之上包裹一层紧凑的二进制协议头：

| 字节偏移 (Byte Offset) | 字段名 (Field Name) | 类型 (Type) | 含义说明 |
| :--- | :--- | :--- | :--- |
| `0 .. 1` | `magic_num` | `u8` | 魔数，固定为 `0x48`（字母 'H'，代表 Hive） |
| `1 .. 2` | `msg_type` | `u8` | 消息类型：`0x01` = Gossip 拓扑控制包, `0x02` = 业务代理数据包 |
| `2 .. 18` | `src_peer` | `[u8; 16]` | 源节点的全局唯一 Peer UUID |
| `18 .. 34` | `dst_peer` | `[u8; 16]` | 目标终端节点的全局唯一 Peer UUID |
| `34 .. 42` | `stream_id` | `u64` | 流 ID，用于区分同一节点发起的并发 SOCKS5 代理连接 |
| `42 .. 46` | `payload_len` | `u32` | 大端序整数（Big-Endian），代表后续真实载荷（Payload）的字节长度 |
| `46 .. ` | `payload` | `Vec<u8>` | 裸二进制载荷（Bincode 序列化的拓扑数据 或 原始 SOCKS5 字节流） |

## 4. 系统核心架构组件设计

### 组件 A：身份与连接管理器 (Identity & Connection Manager)
*   节点首次启动时在本地自动生成一个 16 字节的 `PeerId`（UUIDv4 或加密公钥哈希）并持久化。
*   维护一个线程安全的全局连接池：`Arc<RwLock<HashMap<PeerId, mpsc::Sender<Vec<u8>>>>>`。无论是主动 Dial 连出去的还是被动 Listen 进来的 TCP 连接，握手成功后一律将其发送端通道（Tx）注册进该连接池。

### 组件 B：主动探测器与被动监听器 (Dialer & Listener)
*   **Listener（开门迎客）**：本地绑定默认端口（如 `5678`）。当收到其他跨网段或同网段主机的物理连接时，进行初始化身份验证，绑定连接句柄与对方的 `PeerId`。
*   **Dialer（向外看）**：读取本地极为精简的配置文件（或接收来自 Tauri 前端输入的邻居 IP 数组），通过 `tokio::spawn` 启动死循环，每隔 5 秒定时尝试去物理连接这些已知的“防火墙白名单孔洞”。

### 组件 C：去中心化路由八卦引擎 (Gossip Routing Engine)
*   利用 Rust 的 `petgraph` 库在内存中维护全网拓扑结构图，并用读写锁保护。
*   定时（如每 5 秒）将自己最新的邻居矩阵进行序列化，并通过所有活动的长连接通道向外广播（`msg_type = 0x01`）。
*   收到邻居发来的 Gossip 帧时，更新本地内存图。当需要发送数据时，使用 Dijkstra 算法秒级计算出最优的 `NextHop`（下一跳）。

### 组件 D：本地 SOCKS5 接口与内存中继转发 (In-Memory Relay)
*   在本地启动一个 `127.0.0.1:1080` 的监听服务。
*   当本地业务软件（如 SSH 或浏览器）流量挂载进来时，读取其代理目标，将其映射为目标 `PeerId`，套上 `HiveHeader` 协议头后丢给计算出的 `NextHop` 节点通道。
*   **中继转发逻辑**：当中间节点收到一个数据帧，发现 `dst_peer != current_peer` 时，**仅解析协议头**，通过内存连接池直接匹配到下一跳的 Tx 通道并以 `mpsc` 发送出去。实现真正的**内存零拷贝级数据包接力**，不解包业务数据。

## 5. 实现要求
请为该 Tauri 应用的 **Rust 后端部分** 生成核心的骨架与实现代码：
1.  定义 `PeerId`、`HiveHeader`、`GossipPayload` 以及全局状态 `HiveState` 的结构体。
2.  实现一个异步的高效数据包编解码器（利用 `tokio::io::AsyncReadExt` 和 `AsyncWriteExt` 编写辅助函数），确保自定义二进制帧在 TCP 流上能够正确分包、解包。
3.  编写最核心的路由分发循环函数 `route_packet(state: Arc<HiveState>, header: HiveHeader, payload: Vec<u8>)`，清晰体现系统在收到数据包后，如何条件判断是“本地消费”还是“内存中继转发”。
